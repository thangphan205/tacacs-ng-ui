# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**tacacs-ng-ui** is a full-stack web application providing a graphical interface for managing [tac_plus-ng](https://github.com/MarcJHuber/event-driven-servers) TACACS+ server configurations. It generates and validates TACACS+ config files, manages users/groups/policies, displays AAA statistics, and provides alerting, anomaly detection, and SIEM integration.

## Architecture

### Backend (`backend/app/`)

Follows a strict three-layer pattern:

- **`models.py`** — All SQLModel schemas in one file. Every entity has at least a DB model and a `*Public` DTO. Base class `TimestampModel` adds UTC `created_at`/`updated_at`.
- **`crud/`** — Business logic only. Must **not** raise `HTTPException`. Returns model instances or `None`.
- **`api/routes/`** — HTTP layer only. Translates CRUD results to HTTP responses/status codes. Uses shared deps from `api/deps.py`: `SessionDep`, `CurrentUser`, `get_current_active_superuser`.

Auth is JWT (HS256, 8-day expiry) via `core/security.py`. Settings (env vars) live in `core/config.py` as a Pydantic `Settings` class.

### Frontend (`frontend/src/`)

- **`client/`** — Auto-generated from backend OpenAPI spec. **Never edit manually.** Regenerate with `bash scripts/generate-client.sh`.
- **`routes/`** — TanStack Router file-based routing. `_layout.tsx` wraps all authenticated routes. Route tree is auto-generated into `routeTree.gen.ts`.
- **`components/`** — Chakra UI v3 components. Prefer generic/reusable components over per-entity duplicates.
- **`api.ts`** — Configures the generated fetch client: base URL (`VITE_API_URL` env var) and JWT from `localStorage.access_token`, supplied as the client's `auth` callback so the SDK's `security` array adds the `Bearer` prefix. Also defines **`ApiError`** and registers the error interceptor that produces it.
- **`main.tsx`** — Wires the router and React Query; auto-logouts on `ApiError.status === 401`.

Server state: TanStack React Query v5. Dark mode: next-themes.

#### Generated client conventions

The SDK is generated by `@hey-api/openapi-ts` with the `@hey-api/client-fetch` plugin. `frontend/openapi-ts.config.ts` reads `openapi.json` back to recover each operation's tag, because since 0.99.0 the name builders receive only the operation id string — this is what keeps the `{Tag}Service.methodName()` names stable.

Three call-site conventions follow from that config, and differ from the pre-0.99 legacy client:

- **Parameters are flat** (`paramsStructure: "flat"`) and keyed by their **OpenAPI names**, so path and query params are `snake_case`: `readUserById({ user_id })`, not `{ userId }`.
- **Request bodies are keyed by their schema name**, not `requestBody`: `createUser({ userCreate: data })`, `updateHost({ id, hostUpdate: data })`.
- **Calls resolve to the response body and reject on error** (`responseStyle: "data"` plus the client's `throwOnError`), so `await` yields the payload directly — no `.data` unwrapping, and errors reach `handleError` / React Query as `ApiError`.

The generated `client/core/` directory from the legacy plugin is gone: `ApiError` now comes from `@/api`, and `CancelablePromise` is a plain `Promise`.

### Infrastructure

Docker Compose services: `db` (PostgreSQL 18), `backend` (FastAPI + supervisord + tac_plus-ng + cron), `frontend` (Vite/Nginx), `traefik` (reverse proxy), `adminer` (DB UI), `mailcatcher` (SMTP testing).

**Single-URL routing.** The whole application is served from one host. The backend carries **no Traefik labels** — `frontend/nginx-backend-proxy.conf` proxies `/api`, `/mcp`, `/docs` and `/redoc` to `backend:8000`, and `vite.config.ts` mirrors those prefixes in `server.proxy` for `npm run dev`. Consequences:

- `VITE_API_URL` is **empty by default**, so `apiBaseUrl()` returns `""` and every request is origin-relative — the frontend image is domain-agnostic and needs no rebuild when the domain changes. It is baked in at build time, so setting it *does* require one.
- `MCP_PATH` (default `/mcp`) is mirrored by hand in the nginx conf; changing one means changing the other.
- The proxy uses `resolver 127.0.0.11` with a **variable** `proxy_pass` so nginx re-resolves `backend` per request instead of caching its IP at startup — and still starts when the backend is down.
- uvicorn runs with `--forwarded-allow-ips=*` (`backend/supervisord.conf`). Without it uvicorn ignores `X-Forwarded-Proto` from the non-loopback proxy peer, and Starlette's `Mount` slash-redirect answers `POST /mcp` with an absolute `http://` `Location` that Traefik turns into a body-dropping 301.
- `DOMAIN` is the app's host, not a base domain. `TOOLS_DOMAIN` (falling back to `DOMAIN`) carries `adminer.` and `traefik.`, so they can stay under an existing wildcard cert.
- Playwright's Node-side helpers (`frontend/tests/utils/privateApi.ts`) need an absolute URL and read **`PLAYWRIGHT_API_URL`**, not `VITE_API_URL`.

Local dev URLs:
- App — UI, `/api/v1`, `/docs`, `/mcp/`: http://localhost:5173
- Backend, direct (bypasses the proxy): http://localhost:8000
- Adminer: http://localhost:8080
- Traefik: http://localhost:8090
- MailCatcher: http://localhost:1080

### Seed Data (`backend/app/core/db.py`)

`init_db()` runs on every primary start (`prestart.sh` → `initial_data.py`). Demo TACACS+ data (`DEMO_HOSTS`, `user_admin` / `user_read_only` with password `change_this`, groups, profiles, ruleset) is seeded **only on first initialization** — detected by the `TacacsNgSetting` row not existing yet — and only when `SEED_DEMO_DATA=true`. The `get_or_create_*` helpers are create-only: **never add branches that reset fields on existing rows**, and never seed demo data per name on later starts. Doing so re-created deleted demo accounts with their public password (security report, fixed after 0.6.3). `tests/core/test_init_db.py` guards this. `crud/default_credentials.py` backs the UI warning for anything still on `change_this`.

### TACACS+ Config Generation

Core domain logic in `backend/app/crud/tacacs_configs.py`. Reads/writes config files to `/app/tacacs_config/` (Docker volume), validates syntax using `tac_plus-ng` binary, generates MAVIS LDAP config blocks from template strings.

**Raw-script profiles (#359):** `Profile.raw_script` holds the body of `script { }`; when set, `profiles.profile_generator()` emits it verbatim (re-indented) in place of the Profile Scripts and skips the fallback `action`. A profile is one mode or the other — `crud/profiles.update_profile` refuses raw text on a profile with scripts, `crud/profilescripts` refuses scripts on a raw profile. `app/core/raw_script.check_raw_script()` refuses wrappers, an early-closing `}` (it would end the profile and inject top-level config) and `include`; it runs in the `ProfileCreate` validator and in `update_profile` only when the text changes (a partial update resending stored text must not be blocked), via `normalize_raw_script()`. Its tokenizer mirrors tac_plus-ng's as verified against the binary (`'…'` and `"…"` strings with escapes, `/…/` only after `=~`/`!~`) and **refuses** a `#` not preceded by whitespace, because tac_plus-ng's comment rule there depends on the neighbour — do not loosen it into a guess. The text is emitted verbatim, never re-indented: quoted strings may span lines. `duplicate_profile_names()` blocks Generate when a row and the `profile` Configuration Option define the same name. `POST /profiles/check` syntax-checks unsaved text via `generate_tacacs_ng_config(profile_override=...)`.

### Background Tasks (`backend/app/main.py`)

Four asyncio loops, started from FastAPI lifespan on a primary with the scheduler on:

| Task | Interval | Description |
|---|---|---|
| `_alert_evaluation_loop()` | 5 min | Evaluates enabled alert rules; dispatches notifications |
| `_ml_scoring_loop()` | 24 h | IsolationForest anomaly scoring on 30-day auth stats |
| `_audit_purge_loop()` | 24 h | Purges old audit log entries per retention settings |
| `_stats_collection_loop()` | `stats_interval_minutes` | Runs the three stats scripts for today, then collects from peers |

**Exactly one uvicorn worker runs them (#372).** All 4 workers run the lifespan, so `run_as_leader()` in `app/core/leader.py` elects one by holding a session-level `pg_try_advisory_lock(7461636, 1)` on a dedicated autocommit connection; the others retry every 30 s and take over when the leader's session dies. Without it every alert fired and every stats/SIEM run happened 4 times. A per-iteration xact lock does not work — the runs are sequential, not concurrent. Start new write loops only inside `_start_background_loops()`, never from `lifespan` directly. `tests/core/test_scheduler_leader.py` guards this, using its own lock keys because the test `client` fixture's lifespan may hold the real one.

### Alert Rules & Events (`backend/app/crud/alert_evaluator.py`)

Rules evaluate live TACACS logs (auth/authz log files) and AuditLog table. Fields: `log_type` (auth/authz/config/all), `condition_field`, `condition_operator` (gt/lt/eq/new_value/any_change/created/updated/deleted/activated), `threshold`, `time_window_minutes`, `cooldown_minutes`, `severity`. Triggered alerts dispatch to all enabled `NotificationChannel` rows and write one `AlertEvent` per channel (`sent` / `failed`); with no enabled channel they write one `no_channel` event with `channel_id = NULL`, so Alert History never misses a fired rule. `alertevent.channel_id` is `ON DELETE SET NULL` and the ORM relationship uses `passive_deletes` — deleting a channel must not delete its history.

**Login at Unusual Hour (`crud/login_hours.py`):** a `login_hour` / `unusual` rule compares each successful login's hour with the user's own `AuthenticationHourlyStatistics` baseline (30 log days before the window's first day — the window's own days are excluded so a login is never part of its own history; users with under 7 days are skipped). Hourly rows are collected on every auth stats run **whether or not the rule is enabled**, so the baseline exists the day it is switched on; standbys send them as `authentication_hourly` in `collect-stats`. `_SYSTEM_ALERT_RULES` entries may set `"enabled": False` — this rule does, and seeding is create-only, so an admin's switch is never reset. Like the stats tables, the baseline keeps every user (no `stats_exclusions`).

### Notification Channels (`backend/app/crud/notification_dispatcher.py`)

Supported: Telegram, Slack (Block Kit), Discord, Teams, Webhook, Google Chat, Email.

### Anomaly Detection (`backend/app/crud/ml_anomaly_scorer.py`)

IsolationForest (`contamination=0.05`) trained on 30-day rolling per-username features: avg_daily_fails, stddev_fails, unique_ip_count, deny_ratio. Scores map to risk levels: normal / low / medium / high / critical. Results stored in `AnomalyDetectionResult`.

### AAA Log Statistics & Cron Jobs

Three cron scripts parse yesterday's TACACS logs and aggregate stats into DB:

| Script | Table | Schedule |
|---|---|---|
| `scripts/tacacs_logs_authentication.py` | `AuthenticationStatistics` | 1:00 AM local |
| `scripts/tacacs_logs_authorization.py` | `AuthorizationStatistics` | 1:05 AM local |
| `scripts/tacacs_logs_accounting.py` | `AccountingStatistics` | 1:10 AM local |

Cron is run via `scripts/cron_runner.sh` which sources `/etc/cron_env.sh` (full container environment). Schedule defined in `backend/tacacs-cron-jobs`.

**Timezone:** `scripts/_log_stats_base.py` reads timezone from `TacacsNgSetting.timezone` (DB-stored, editable in UI under TACACS NG Settings). Falls back to `TZ` env var, then UTC. The setting is seeded from `TACACS_TIMEZONE`, which defaults to `TZ`, so set `TZ=Asia/Ho_Chi_Minh` in `.env`. This controls which local day is "today" / "yesterday" when scanning log files.

**One definition of "day" (#356):** tac_plus-ng names files and stamps lines in local time, so every "today" — read path, collectors, alert evaluator, frontend — must be the log-timezone day: `local_today()` / `local_date()` in `_log_stats_base.py` on the backend, `useLogDays()` (`frontend/src/hooks/useLogDays.ts`, from `TacacsNgSetting.timezone`) on the frontend — not the browser's zone, which differs for admins elsewhere. Label a YYYY-MM-DD with `formatISODate()`, never `new Date("YYYY-MM-DD")` (UTC midnight, the previous day west of UTC). Show API timestamps with `formatDateTime()` (viewer's zone, zone named). Never `datetime.now(timezone.utc).date()` or `toISOString()` for a log day. `log_date` on the three stats tables is a **`date`** column: a timestamp there was shifted a day by the PostgreSQL session time zone. `tests/crud/test_log_day.py` guards this.

Pass a date argument to run for a specific date: `python scripts/tacacs_logs_authentication.py 2026-05-13`

### Statistics Exclusions (`backend/app/crud/stats_exclusions.py`)

`StatsExcludedUser` rows (username or `*` glob, case-insensitive) hide service accounts from AAA statistics and dashboards. **Applied when statistics are read, never when they are collected**: the stats tables keep every user, so the alert evaluator's new-user/new-IP baseline, anomaly scoring, SIEM forwarding and peer `collect-stats` stay complete. `tests/api/routes/test_stats_exclusions.py::test_ingest_and_alerting_never_apply_exclusions` fails if any of those modules imports `stats_exclusions`. Read endpoints take `include_excluded` and return the applied patterns in `excluded_users`.

Today's live numbers in `crud/aaa_statistics.py` go through `_today_rows()`, which caches **unfiltered** per-user rows for 60 s. Exclusions are applied after the cache, so a list change shows up at once in all 4 uvicorn workers. Do not move the filter inside the cache.

### SIEM Forwarding (`backend/app/crud/tacacs_siem.py`, `crud/siem_tailer.py`)

Configured in the UI (**Admin → SIEM Integration**, `frontend/src/routes/_layout/admin/siem.tsx`, superuser-only `/api/v1/siem/{config,test,status}`), stored in the singleton `SiemConfig` row (id=1; webhook token Fernet-encrypted via `encrypt_secret`, exposed only as `webhook_token_is_set`). The `SIEM_*` env vars only **seed** that row on first primary start (`core/db._seed_siem_config`, create-only like the other seeds); after that the UI owns it. The stats scripts no longer forward anything — the old daily per-(user, device, source, result) records are gone.

- **TACACS+ events:** `scripts/siem_shipper.py` is a supervisord program on **every node** (once per container, so no leader lock), reading `SiemConfig` from the DB (the replica on a standby) every 10 s. `LogTailer` follows today's `/var/log/tacacs/YYYY/MM/<type>-YYYY-MM-DD.log` per enabled type, parses lines with `core/tacacs_log_parse.parse_log_line` (shared with the TACACS Logs page — `crud/` and scripts must not import `api/routes`), and sends one event per line. Offsets persist in `/var/log/tacacs/.siem/offsets.json` (a dot-directory: `GET /tacacs_logs/files` skips dot-entries, otherwise the state file is listed as a log). A file with no offset at start or on enabling a type starts at **EOF** (never replay history); a file that appears while running, or today's file when yesterday's was being tailed, starts at 0. Disabling a type drops its offsets. Delivery is **at-least-once for the deciding sink** — the webhook if set, else syslog (offset moves only once it took the batch; failure → 2→60 s backoff before reading newer lines). With both, syslog is sent once per batch and not re-sent for a pending webhook retry. `_ship_file` returns done / partial / more / failed: yesterday's file blocks today's only on *more* or *failed* — an unfinished last line must not block the new day. Batches per tick are capped (`MAX_BATCHES_PER_TICK`). Status goes to `/tmp/siem_shipper_status.json`, read by `GET /siem/status` on the node serving the request. A failed first config read must not be treated as "disabled" — that would drop all offsets.
- **Audit entries:** `crud/audit_logs._forward_to_siem` reads `SiemConfig` on the same session and, when `enabled and ship_audit`, sends from a daemon thread. Audit rows exist only on the primary.

Syslog is built by hand, not with `logging.handlers.SysLogHandler` (#373): that handler ends TCP messages with NUL, which Graylog's default TCP input silently drops, and sends no timestamp or hostname. Messages are RFC 5424 with HOSTNAME = node name and MSGID `-` (Graylog 5.2 leaves a MSGID inside `message`), LF-terminated over TCP, sent over one cached connection per process with a 60 s pause after a failure. `tests/crud/test_tacacs_siem.py` checks framing against real local sockets.

**tac_plus-ng's own alternative — `TacacsNgSetting.remote_syslog_destination`:** when set, `_remote_log_block()` in `crud/tacacs_configs.py` adds a `log remotelog { destination = … }` plus one `<type> log = remotelog` line per log type (a comma list is rejected by tac_plus-ng) **after** the local log lines, which must stay: stats, alerts and the logs page read those files. tac_plus-ng then sends RFC 3164 UDP syslog for every event from every node. `check_remote_syslog_destination()` allows only `IPv4[:1-65535]` — verified against the binary: a hostname silently creates no log, an IPv6 port is ambiguous, and `-P` accepts junk like `:99999` or `;x`, so this validator is the only real check; the generator re-checks and drops a bad stored value rather than interpolate it. The syslog HOSTNAME is the container hostname, which `docker-compose.yml` sets to `${NODE_NAME}` for the backend — keep that line.

### Audit Logging (`backend/app/crud/audit_logs.py`)

Records CREATE/UPDATE/DELETE/ACTIVATE actions on entities with user_id, email, IP, user-agent, old/new values. Auto-purges via `AUDIT_LOG_RETENTION_DAYS` (default 90) and `AUDIT_LOG_MAX_ROWS`. Routes call `audit_logs_crud.log_entity_action()` after mutations.

### MCP Server (`backend/app/mcp_server/`)

Model Context Protocol endpoint letting an LLM client inspect TACACS+ entities, render config previews, syntax-check config text, and — with `mcp:write` — create/update/delete entities. On by default (`MCP_ENABLED=true`); set to `false` to disable. See `docs/en/mcp-server.md`.

**It cannot deploy, and must never be able to.** No tool saves a config file, activates one, or reloads tac_plus-ng — an entity edited over MCP sits in the database until a human presses Generate + Activate in the UI. `tests/mcp/test_no_config_writes.py` walks the AST of every module in the package and fails if one gains a reference to `create_tacacs_config` / `update_tacacs_config` / `delete_tacacs_config`, a write-mode `open()`, or a subprocess import. Do not weaken that test to make a change pass.

Mounted at `settings.MCP_PATH` (default `/mcp`) directly on `app` in `main.py` — **never** under `api_router`, since a `Mount` must stay invisible to `custom_generate_unique_id` and OpenAPI generation. Canonical URL has a trailing slash.

| File | Role |
|---|---|
| `server.py` | `build_mcp()` factory, `build_http_app()`, `MCPMountApp` ASGI shim, `mcp_lifespan()` |
| `auth.py` | `ApiKeyAuthMiddleware` (401 before protocol handling), `principal_from(ctx)`, scope guards |
| `tools.py` | the 15 tool registrations via `_tool()`; `_require_read` / `_allow_write` / `_allow_unredacted` guards |
| `service.py` | read-side DB work — plain sync functions taking a `Session` |
| `write_service.py` | write-side DB work — the `WRITABLE` registry adapting each entity's CRUD kwargs to one signature |
| `redact.py` | two-pass secret masking |
| `resources.py` | tac_plus-ng syntax reference, entity schema, active config, authoring prompt |

Constraints that are load-bearing:

- **`stateless_http=True` is mandatory** — supervisord runs `uvicorn --workers 4`, four processes with no shared memory, so in-process session state would miss on most requests.
- **The four transport settings live on `build_http_app()`, not the constructor** — `stateless_http`, `json_response`, `streamable_http_path` and `transport_security` were `FastMCP(...)` arguments before mcp 2.0; `MCPServer` takes them on `streamable_http_app()`. That call is also what lazily builds the session manager, so it must happen before `session_manager` is read.
- **Tools must be `async def` + `run_in_threadpool`** — the server calls sync tool functions inline on the event loop.
- **Anticipated failures must reach the model as `ToolError`** — mcp 2.x sends a tool's exception text to the client only for `ToolError`; everything else is treated as a crash and reported as a bare `Error executing tool <name>`. `_tool()` in `tools.py` wraps each registration and translates `McpAuthError` / `LookupError` / `ValueError`, so scope refusals and validation messages stay readable. `service.py` and `write_service.py` keep raising plain builtins — the transport-shaped exception is applied at the boundary, the same way `crud/` never raises `HTTPException`.
- **`transport_security` must be passed explicitly** — DNS-rebinding protection is auto-enabled when `host` is loopback (its default), which rejects the public `Host` header forwarded by nginx and Traefik.
- **`session_manager.run()` is once-per-instance** — hence a fresh `MCPServer` per lifespan and the `MCPMountApp` shim. This is also why `tests/conftest.py`'s `client` fixture is session-scoped.
- **Write tools check the node role themselves** — `require_primary_node()` is a FastAPI dependency and MCP tools are not routes, so `_allow_write()` repeats the standby check inline.

### API Keys (`backend/app/crud/api_keys.py`)

Machine credentials for MCP. Hashed with HMAC-SHA256 keyed on `SECRET_KEY` (**not** a password hash — argon2 and bcrypt both embed a random salt, which makes indexed lookup impossible, and their deliberate 50-250ms of blocking CPU would land on every MCP tool call). Superuser-gated CRUD at `/api/v1/api_keys`, soft revoke, audit-logged. Plaintext is returned exactly once at creation.

Scopes are two access levels plus one opt-in: `mcp:read` (read-only), `mcp:write` (read-write — subsumes `mcp:read`, and additionally requires the key's user to be a superuser), and `mcp:secrets` (unredacted output, superuser-only, audit-logged). The set lives in `ALLOWED_API_KEY_SCOPES` in `models.py` and is enforced by a `field_validator` on **`ApiKeyCreate`, not `ApiKeyBase`** — `ApiKeyPublic` and the table model also inherit Base, so validating there would make a row with an unrecognised scope string unreadable and unrevokable.

Managed in the UI under **User Settings → API Keys** (`frontend/src/components/UserSettings/{ApiKeys,AddApiKey,RevokeApiKey,McpGuideModal,McpClientGuide}.tsx`), a tab added to `settings.tsx` only when `currentUser.is_superuser`. The create form uses `noValidate` so react-hook-form owns validation — Chakra's `Field required` sets a native `required` that would otherwise block submit before RHF runs. The access-level radio and secrets checkbox deliberately sit outside a `Field`, whose context would point every nested input's `aria-labelledby` at the Field label.

The TACACS Configs page (`frontend/src/routes/_layout/tacacs_configs.tsx`) shows a `PendingChangesAlert` that diffs `GET /tacacs_configs/preview` against `GET /tacacs_configs/active` client-side, so entity edits made elsewhere — the entity pages, or an MCP write key — surface as "unapplied changes" rather than sitting unnoticed. `/active` 404s when nothing has been activated yet; the query uses `retry: false` and treats the error as a valid state.

### Password Hashing

Two independent schemes — do not confuse them:

| | Library | Format | Where |
|---|---|---|---|
| **Login passwords** | `pwdlib` — `PasswordHash((Argon2Hasher(), BcryptHasher()))` | `$argon2id$` | `core/security.py` |
| **TACACS+ device users** | `passlib` — `sha512_crypt` | `$6$rounds=...$` | `crud/tacacs_users.py` |

`verify_password()` returns **`tuple[bool, str | None]`**, not a bool — the second item is a rehash to persist. `crud.users.authenticate()` writes it back, upgrading pre-migration bcrypt hashes to argon2 on next login (skipped on `NODE_ROLE=standby`).

passlib survives only for the TACACS scheme because tac_plus-ng parses `$6$rounds=...$` directly. **Never add `"bcrypt"` to a passlib `CryptContext` here**: its bcrypt backend probes for an old OpenBSD bug by hashing a 255-byte secret, which bcrypt ≥ 5.0 rejects with `ValueError`, breaking every hash and verify. `tests/core/test_security.py::test_passlib_bcrypt_backend_is_never_loaded` guards this.

### Authentication Providers (`backend/app/api/routes/oauth.py`)

- **Google OAuth2** — `google_id` column on User; HMAC-state validation
- **Keycloak OIDC** — `keycloak_id` column on User; HMAC-state validation
- **Microsoft (personal accounts + Entra ID)** — `microsoft_id` column on User. One provider; the `tenant` setting (`common`/`organizations`/`consumers`/tenant ID) picks who may sign in. Identity comes from the id_token (signature unchecked — it arrives straight from the token endpoint over TLS), matched on `aud`. **Existing accounts are linked by email only for a single tenant or a personal (MSA) account** — Entra's `email` claim is mutable and unverified, so linking on it in multi-tenant mode would allow account takeover (nOAuth); `get_or_create_microsoft_user` returns `None` and the route answers 403. Do not relax that.

All three providers derive their redirect URI from `FRONTEND_HOST` when neither the admin form nor env sets one (`_default_redirect_uri` in `oauth.py`); the admin form prefills the same value via `FieldDef.defaultValue`.
- **WebAuthn / Passkeys** — `WebAuthnCredential` + `WebAuthnChallenge` tables; `passkeys.py` CRUD

### High Availability (`backend/app/api/routes/sync.py`)

Multi-node active-passive HA via PostgreSQL streaming replication + config fan-out. See `docs/en/high-availability.md` for full setup guide.

**Env-only settings** (require restart):
- `NODE_ROLE` — `primary` or `standby`; controls DB write access and `require_primary_node()` dep
- `INTERNAL_SYNC_TOKEN` — shared secret for inter-node API calls

**All other HA settings** are DB-driven (`HaConfig` table, id=1) and editable via the HA UI without restart: `node_name`, `sync_mode`, `scheduler_enabled`, `stats_interval_minutes`.

**Peer management:** `HaPeerNode` table (CRUD via `GET/POST/PATCH/DELETE /api/v1/sync/peers`). On first primary startup, `PEER_BACKEND_URL`/`PEER_NODES` env vars are seeded into `HaPeerNode` automatically. Config sync fans out to all enabled peers.

**Key files:**
- `backend/app/api/routes/sync.py` — all HA API routes
- `backend/app/crud/tacacs_configs.py` — `_notify_peer_reload()` (auto-sync fan-out)
- `backend/scripts/config_sync_watcher.py` — standby auto-sync watcher (polls DB every 10s)
- `backend/app/models.py` — `HaConfig`, `HaPeerNode`, `HaNodeState`, `HaState`

## Code Conventions

### Python

- Python 3.12+ union syntax: `str | None`, `list[str]` — never `Optional`, `List`
- Always timezone-aware datetimes: `datetime.now(timezone.utc)`, never `datetime.utcnow()`
- Every timestamp column is `timestamptz`: declare datetime fields with `sa_type=TZ_DATETIME` (`models.py`); `tests/core/test_timestamps.py` fails on a naive column. `core/db.py` pins every app session to `TimeZone=UTC`, so values come back aware UTC and the API sends `…Z` whatever zone each node's db server runs in. Before migration `c3f8e2a91b47`, columns were naive and held the db server's wall time, which code read as UTC — off by the server's offset (alert cooldowns, API output). Alembic's engine is deliberately not pinned
- `logging` module only, never `print()` in production code
- Return type annotations required on all functions
- Error messages in `HTTPException` must match the actual entity (avoid copy-paste errors)

### TypeScript / React

- No `any` — use proper types or `unknown`
- Hooks only inside React components or custom hooks, never in plain functions
- Indentation: 2 spaces, double quotes, Biome enforced

### API Patterns

- Pagination: `skip`, `limit`, `sort_by`, `sort_order` query params
- UUIDs as primary keys throughout
- `operationId` format `{tag}-{name}` (controls generated client method names)
